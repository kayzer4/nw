# Nightwatcher Clean — дизайн MVP

## Цель

Создать отдельную репу `nightwatcher-clean` для базовой играбельной модели ночного города. Сохранить стек Next.js 16, React 19, TypeScript, React Three Fiber и Three.js. Упростить систему до уровня, где правила города, состояние игры и отображение можно понимать и менять независимо.

## Архитектура

Это один Next.js-проект. `app/` содержит страницы и Route Handlers; `src/server/` — серверную подготовку/проверку уровней и чтение пресетов; `src/game/` — чистую доменную симуляцию; `src/client/` — UI и 3D-отображение. Границы импорта запрещают клиентскому графу зависеть от `src/server/` и данных разметки.

Серверная функция `src/server/level-builder.ts` использует конфиги моделей как входные данные, выбирает/раскладывает ассеты по числовому seed, нормализует формат пресета и проверяет ссылки на GLB. Она переносит алгоритм `CityGenerator`: поле 6×6, случайные блоки размером 3–6 клеток, дороги шириной в клетку вокруг блоков и до 20 попыток для совместимого соединения дорожных клеток. Модель каждой дорожной клетки выбирается по `roadConnect*` из JSON. Фонари берутся из `lights` дорожных моделей и отбираются жадным покрытием всех полуметровых точек циклических маршрутов с учётом радиуса и зданий; оставшиеся пробелы закрываются фонарями у края дороги. Seed от 0 до 4294967295 использует тот же Park–Miller RNG, что и исходный проект. `GET /api/levels` возвращает каталог доступных районов; `GET /api/levels/[id]` собирает выбранный каталоговый район, а `GET /api/levels/generate?seed=...` собирает произвольный. Одинаковый seed возвращает одинаковый город. Скрипт `tools/build-levels.ts` создаёт checked-in пример для default seed, не перезаписывая каталог. Route Handlers реализуются по локальной документации Next.js 16 и отвечают стандартными `Request`/`Response`.

Пресет содержит только данные для отображения и игры: ID/название/параметры уровня, размещённые здания и фонари (asset URL, transform, нормализованные параметры света), точки/маршруты жителей и игровые значения. В нём нет тегов, правил выбора модели, аттрактор-конфигов редактора или логики генератора.

## Игровой цикл и производительность

Состояние разделено на неизменяемое описание уровня, игровую сессию и визуальные объекты. При загрузке один раз строятся пространственные группы и связи «фонарь → затрагиваемые зоны/жители» с ранним геометрическим отсевом. Пересчёт состояния происходит только после действия игрока и на редком фиксированном тике симуляции (например, раз в секунду); нет полного перебора NPC × фонари × здания в `useFrame`.

`useFrame` используется только для непрерывной визуальной интерполяции Three.js-объектов и не меняет React-состояние. Игровое время, энергия и удовлетворённость обновляются независимо от корневой 3D-сцены; HUD подписывается только на нужные значения. Статичная геометрия уровня создаётся при загрузке и не пересобирается от тиков.

MVP-петля: выбрать уровень → начать ночь → включать/выключать фонари → сохранять энергию и достаточное освещение для жителей → дожить до конца смены. Поражение наступает при исчерпании энергии или падении удовлетворённости до порога; победа — по окончании ночи. Прогресс кампании и последний использованный seed хранятся в `localStorage` с версионируемой схемой и безопасным сбросом повреждённых/устаревших данных. Игровой интерфейс позволяет выбрать район из каталога, задать seed вручную или запросить случайный.

## Контент и минимальный объём

Переиспользуются необходимые GLB и семантика конфигов моделей из исходного проекта; бинарные модели и исходная репа не редактируются. В новый проект переносится только нужный набор ассетов. Никакого редактора, ragdoll, погодных эффектов, динамики окон, сложной физики, аккаунтов, базы данных или серверного сохранения прогресса в MVP нет.

## Проверка результата

- Скрипт собирает детерминированные пресеты и сообщает об отсутствующих GLB/некорректных данных.
- API отдаёт список и отдельный готовый пресет без генерации на запросе.
- Клиент может загрузить уровень, начать смену, переключить фонарь, завершить победой/поражением и восстановить прогресс после перезагрузки.
- `src/client` не импортирует серверный код и сырые конфиги разметки.
- Таймер/метрики не вызывают ререндер корневой сцены; симуляционный тик не привязан к частоте кадров.
- Проект собирается командами из нового README; визуальную игру можно открыть локально в браузере.
